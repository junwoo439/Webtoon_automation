# ToonPace 0.1.3

## 휴대폰 사용

- ▶로 시작하고 Ⅱ로 정지합니다. ⋮를 끌어 조작부 위치를 옮길 수 있습니다.
- 자동 읽기 대기 중 웹툰 화면을 누르면 일시정지하도록 투명한 터치 영역을 추가했습니다. 첫 터치는 정지에 사용됩니다. 멈춘 뒤 다시 터치하면 웹툰 앱을 조작할 수 있습니다.
- 자동 스와이프/다음 화 탭을 주입하는 짧은 동안은 터치 영역을 숨깁니다. 이 구간의 직접 조작 감지는 Android 이벤트/제스처 취소에 의존하므로 모든 터치를 잡는다는 보장은 없습니다. Ⅱ 버튼은 별도로 유지됩니다.
- ⋮ 메뉴에서 −/+로 0.5~5배 속도를 선택합니다. 읽기 대기시간, 스와이프 시간, 스크롤 안정화 대기에 적용됩니다. 화면 인식 처리시간이 있어 실제 이동량이 정확히 5배가 되지는 않습니다.
- 다음 화 자동 이동 상태를 ⋮ 메뉴에서 확인하고 변경할 수 있습니다. 처음에는 무료 회차에서 확인하세요.

## 0.1.3 변경 사항

- 접근성 클릭 이벤트를 보내지 않는 화면에서도 읽기 대기 중 터치로 정지할 수 있도록 입력 방식을 변경했습니다. 조작 버튼은 터치 영역 위에 둡니다. 정지, 동의 철회, 서비스 종료 시 터치 영역도 비활성화됩니다.
- 스크롤 끝에서 같은 위치인데 이동량 이벤트만 계속 오는 경우를 구분합니다. 현재 스와이프에서 최대 위치에 도달했다는 정보와 안정된 화면이 확인되면 다음 화 후보로 판단합니다.
- 다음 화 탭 전에는 앱/화면, 버튼 문구/위치, 결제·로그인 안내를 다시 확인합니다. 전체 화면 픽셀이 그대로여야 한다는 조건을 제거해 작은 화면 변화로 이동이 취소되는 문제를 줄였습니다.
- ‘다음 회차 보기’ 문구를 추가 인식합니다. 실제 카카오페이지 화면의 버튼 인식과 이동은 실기기 확인이 필요합니다.
- 최고 속도를 2배에서 5배로 확대하고 빠른 속도에서는 고정 900ms였던 안정화 대기를 최소 300ms까지 줄입니다. 스크롤 이벤트가 계속되면 안정화를 기다립니다.

## 빌드

Android Studio에서 프로젝트 루트를 열고 SDK Platform 35 / Build-Tools 35.0.0을 설치하세요. Gradle 8.11.1, JDK 17 이상을 사용합니다.

- `./gradlew :app:assembleDebug :app:lintDebug`
- `sh test-core.sh`

Windows에서는 SDK를 Android Studio GUI로 설치한 뒤 IDE 또는 build-windows.cmd를 사용하세요. 결과는 app/build/outputs/apk/debug/app-debug.apk입니다.

실행한 검사와 미검증 범위는 TEST-RESULTS.md를 참고하세요.
